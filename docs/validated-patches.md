Every `.staticinfoheader` now lists `[key][u32 len][name][u32 offset][u32 size]` per row, and every body row opens `[key][u32 row index]` before the unchanged 2.05.01 remainder (`binary::static_header`). iteminfo keeps `string_key` as a zero-width `HeaderName` filled from the header (`parse_iteminfo_with_header`); skill and stringinfo read and write the 2.06 layout byte-identically; every other table parser rebuilds the pre-2.06 layout in memory (`static_header::legacy_pair` / `to_legacy_layout`), so their APIs did not change. **The eight body-only bridges (mission, character, knowledge, stage, gimmick, quest, quest gauge, sub-level) cannot find rows in a 2.06 body alone**: they gained additive `*_load_from_bytes_with_header` C ABI (and their `*_load_from_file` reads the header next to the body), and `crimson_iteminfo_load_from_bytes_with_header` carries the item names. The only field drift the bridges hit: `dyecolorgroupinfo` color records grew from 8 to 22 bytes, because 2.06 inlined the anonymous conditions (`conditioninfo` rows named by their expression, 2,564 removed) as `01` + compiled bytecode wherever a table referenced them by `ConditionInfoKey` (storeinfo, factionnode, levelinfo, dropsetinfo, board, questinfo, globalgameevent, dyecolorgroupinfo, characterinfo, gimmickinfo; "Inlined conditions (2.06)" in [`scripts/CLAUDE.md`](../scripts/CLAUDE.md)). characterinfo also gained two zero bytes in its fixed head (`FactionKey` byte 149 → 151). Content: base iteminfo lost 1005744 (row 3,340) and gained 1007080 (row 6,076), so CE item IDs 3,340–6,075 moved down by one (the 1,311 DLC-only IDs and most others kept theirs; IDs 3,771–3,797 and 6,941–7,015 were also reordered); `iteminfo.dlc_01` now repeats 6,907 base items (244 before) and the game uses those DLC rows; DLC item names moved into the base PALOC. The in-game key array widened again, to 48-byte elements. Save body unchanged.

**2.05.01 moved the iteminfo layout inside minor 5** (paver `2/5/1`, build `0x4ef4be86`, `dlc_01` revision 9, Steam build 26776744, verified 2026-11-21). Two `u8`s: `unk_post_discardable` after `discardable` on every row (1 on exactly the items with `item_type` 102 / 103), and a trailing byte on every `PageData` element. Item count and order are unchanged, so the CE item IDs stand. `PARSER_MIN_GAMEDATA_PATCH` is 1: a 2.05.00 install fails the gate. Skill and 255 of 277 base tables are byte-identical to 2.05; the other tables are content-only. That makes two patch-level layout drifts in a row (2.04.08, 2.05.01).

**2.05 named the two dye tables' rows** (paver `2/5/0`, `dlc_01` revision 8, Steam build 26636972, verified 2026-11-13). `partprefabdyeslotinfo` and `partprefabdyetexturepalleteinfo` rows, which had an empty name since 2.04, now carry one; both parsers read either. iteminfo, skill, every other table and the save body are content-only. **The in-game item key array widened to 24-byte elements** (`key, offset, u64 pointer, u64 0`), which broke the CE dumper's AOB; base rows come first in header order, then the DLC's own rows. See the 2.05 row in the table above.

**2.04.08 changed a layout without moving the minor** (paver `2/4/8`, build `0xe4d53a97`, `dlc_01` revision 7, verified 2026-11-07). iteminfo gained two `CString`s after `filter_type` (empty except on seven DLC ship cannons); every other table, skill and the PALOC are content-only. Because `(major, minor)` no longer identifies a layout, `PARSER_MIN_GAMEDATA_PATCH` (= 8) and `crimson_parser_min_gamedata_patch()` were added: a 2.04.03 install now fails the gate instead of mis-parsing. **A patch-level update is not safe to assume content-only — run the suite on every Steam update, not only on minor bumps.**

**2.04 rewrote the row layout and the archive index** (paver `2/4/3`, Steam build 26345091, verified 2026-11-01). Every named static-info row opens `[u32 len][name][key]` now (`binary::row_head`), iteminfo and skill were reordered, most top-level iteminfo lists gained a presence byte (`CFlaggedArray`), and strings became hashes. Every PAMT moved to relative-parent tries plus an extension table, and the PAPGT lost its checksum for a 64-byte trailer that looks like a signature: **an edited `0.papgt` carries a stale one, and whether the game still loads mods on 2.04 is not established.** A new `dlc/dlc_01/` tree mirrors the install (Steam depot 5001841, DLC app 5001840: installed only for owners). Nothing merges it into the base tables automatically; the factionnode / knowledge / faction / characterinfo bridges and the item → dye-row join (`item_part_prefab`) merge it only when the caller asks (`*_merge_dlc_from_bytes`, 2026-11-27, [`docs/c-abi-surface.md`](c-abi-surface.md)), and `keys.txt` covers the base table only. Re-saving on 2.04 strips equipment from most hired mercenaries, which is the game and not the decoder. The record is the 2.04 row of the table above and the "ItemInfo (2.04)" section in [`archive/iteminfo-layout-history.md`](archive/iteminfo-layout-history.md).

**Save bodies carry absence markers (2026-09-18).** The engine writes one `0x01` byte for every *absent* dynamic array (`meta_kind` 3) and object list (6 / 7) and nothing for other absent fields; present arrays and lists open with a `0x00` tag and a u32 count. The decoder used to skip absent fields without consuming anything, so each marker was read as the start of the next field (a mercenary's `_currentHp` read 1,134,700,311,674,881 instead of 1,032) and the leftovers hid in list-header / dynamic-array "variants" and `trailing_pad` — byte-exact round-trips never noticed. `walk_fields_with_markers` now decodes the engine's layout first, with the legacy walk as a fallback that no measured save needs (12 live saves 1.10–2.03 + the 1.09 / 1.10 fixtures; `test_save_body_absent_markers_every_live_save`). Save *schemas* still move per patch, so an element captured on one patch goes into another through the name-keyed element templates (`src/c_abi/element_template.rs`). Details: [`docs/c-abi-surface.md`](c-abi-surface.md), "Absence markers".

**2.03 ships one iteminfo drift and a new PALOC container** (paver `2/3/0/0x03045138`, verified 2026-09-18). `inventory_info_list` gained a tenth InventoryKey slot (`[u16; 10]`, every item +2 B): it reads 0xFF except on the 59 `Trade_*_PackedInVehicle` items, where it is 21 `Ship` — the same sentinel and the same 59 items that folded slot 8 into the array in 1.16, and those 59 are what pin it after slot 8. Separately, every `.paloc` file (15 languages × 39 namespaces) is now wrapped in a 0x200-byte `"paloc"` header + one LZ4 block around the unchanged entry list; `parse_paloc_bytes` failed on all of them until `binary::paloc::unwrap_container` went into every reader (Python and both C-ABI loaders — the downstream editor would otherwise have lost every display name). The game's compressor is not lz4_flex's, so a container roundtrips through its body, like a save. A large English copy pass retitled nine curated quest rows, which `curated_titles_match_live_install` flagged as designed. Skill (2,069 entries), the save body and all 30 gamedata bridges are content-only; the pins that moved were row counts.
