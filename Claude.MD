# crimson-rs — Crimson Desert Archive Toolkit

Rust library with Python bindings (via PyO3/maturin) for reading, writing, and modding Crimson Desert game archives. **Personal-playground fork — not intended to flow back to the `potter420/crimson-rs` upstream.** Supports Crimson Desert 1.05–2.03 across the PALOC / PAZ / PAMT containers and the save format. The iteminfo parser targets the **latest patch only** — currently 2.03, byte-perfect on 6,816 items (verified on the live 2.03 install, 2026-09-18).

**Save bodies carry absence markers (2026-09-18).** The engine writes one `0x01` byte for every *absent* dynamic array (`meta_kind` 3) and object list (6 / 7) and nothing for other absent fields; present arrays and lists open with a `0x00` tag and a u32 count. The decoder used to skip absent fields without consuming anything, so each marker was read as the start of the next field (a mercenary's `_currentHp` read 1,134,700,311,674,881 instead of 1,032) and the leftovers hid in list-header / dynamic-array "variants" and `trailing_pad` — byte-exact round-trips never noticed. `walk_fields_with_markers` now decodes the engine's layout first, with the legacy walk as a fallback that no measured save needs (12 live saves 1.10–2.03 + the 1.09 / 1.10 fixtures; `test_save_body_absent_markers_every_live_save`). Save *schemas* still move per patch, so an element captured on one patch goes into another through the name-keyed element templates (`src/c_abi/element_template.rs`). Details: [`docs/c-abi-surface.md`](docs/c-abi-surface.md), "Absence markers".

**2.03 ships one iteminfo drift and a new PALOC container** (paver `2/3/0/0x03045138`, verified 2026-09-18). `inventory_info_list` gained a tenth InventoryKey slot (`[u16; 10]`, every item +2 B): it reads 0xFF except on the 59 `Trade_*_PackedInVehicle` items, where it is 21 `Ship` — the same sentinel and the same 59 items that folded slot 8 into the array in 1.16, and those 59 are what pin it after slot 8. Separately, every `.paloc` file (15 languages × 39 namespaces) is now wrapped in a 0x200-byte `"paloc"` header + one LZ4 block around the unchanged entry list; `parse_paloc_bytes` failed on all of them until `binary::paloc::unwrap_container` went into every reader (Python and both C-ABI loaders — the downstream editor would otherwise have lost every display name). The game's compressor is not lz4_flex's, so a container roundtrips through its body, like a save. A large English copy pass retitled nine curated quest rows, which `curated_titles_match_live_install` flagged as designed. Skill (2,069 entries), the save body and all 30 gamedata bridges are content-only; the pins that moved were row counts.

What each patch changed, and how each drift was pinned, is in the "Validated patches" table in [`scripts/CLAUDE.md`](scripts/CLAUDE.md). What carries forward to every future patch:

- **Archive paths are resolved, never hardcoded.** Every library entry point takes its directory from the caller. The gamedata / PALOC layout lookup lives in [`scripts/gamedata_layout.py`](scripts/gamedata_layout.py) and `src/binary/gamedata_layout.rs` (test-only), both newest-layout-first with fallback — a new layout is one entry at the front of each list.
- **`PARSER_TARGET_GAMEDATA_MAJOR` / `_MINOR` are read as a pair** — the minor resets on a major bump (paver `2/0/0` followed `1/18/0`). Current: 2.03, paver `2/3/0/0x03045138`.
- **A new field inside an all-zero run can't be located by byte diff** — every candidate position round-trips. Settle it by which reading keeps the neighbours' known value distributions intact, and diff against the kept previous-version binary in `gamedata-bin/` before arguing from statistics.
- **The 3-byte `..._lookup_slot_mask` C ABI is a partial read** since the 2.01 dye-mask widening; the full field is `..._lookup_slot_mask_full` / `..._lookup_slot_extra_layer_mask_full` (see [`docs/dye-editor-scope.md`](docs/dye-editor-scope.md)).
- **Curated quest tables are keyed and tested** — `curated_titles_match_live_install` fails on the next retitle.

Previous-version parsers: use the `git archive HEAD` + `maturin build` + `pip install --target` route in [`scripts/CLAUDE.md`](scripts/CLAUDE.md) ("Sibling-parser").

This file is intentionally a **minimal index** — detailed reference lives in the linked docs.

# Development
- **Build (Python wheel):** `maturin develop` (in a venv; the project uses `.venv/`) — auto-activates the `python` feature via `[tool.maturin]` in `pyproject.toml`. **The venv must be Python 3.12** — the wheel builds `abi3` for Python ≥ 3.12, so create `.venv` from a 3.12 interpreter (`py -3.12 -m venv .venv` or `C:\Users\<you>\AppData\Local\Programs\Python\Python312\python.exe -m venv .venv`), `source .venv/Scripts/activate`, then `maturin develop --release`. Run `export_for_ce.py` / any parsing from this same venv. **Stale-build gotcha — check this FIRST on a new patch, before suspecting schema drift.** Two independent copies can go stale: (a) a stray `crimson_rs` in the *global* Python 3.12 `site-packages` from an earlier `pip install`, and (b) **the venv's own `.pyd`** — `maturin develop` installs `crimson_rs` as editable, so `crimson_rs.__file__` points at the in-tree `python/crimson_rs/__init__.py` and *looks* current while the sibling `python/crimson_rs/crimson_rs.pyd` is whatever was last built. On 2026-08-09 that `.pyd` was 30 days old (a 1.13-era build) on a tree at 1.16. Either one silently mis-parses a new patch. So: `maturin develop --release` **before** any parsing run on a fresh patch, and sanity-check with `python -c "import crimson_rs, pathlib; p=pathlib.Path(crimson_rs.__file__).parent/'crimson_rs.pyd'; print(p.stat().st_mtime)"`. If you maintain the global install too, refresh it with `<Python312> -m pip install --force-reinstall --no-deps target/wheels/crimson_rs-*.whl`.
- **Build (C# / native):** `cargo build --release --features c_abi` → `target/release/crimson_rs.dll` (cdylib, ~1.2 MB) **and** `crimson_rs.lib` (staticlib, ~15 MB) in one pass. PyO3 is **not** linked; [`.cargo/config.toml`](.cargo/config.toml) statically links the MSVC CRT so the dll has zero transitive DLL deps. Downstream integration recipe (LoadLibrary vs NativeAOT single-file): [`docs/c-sharp-nativeaot-integration.md`](docs/c-sharp-nativeaot-integration.md).
- **Feature flags:** `default = []` (bare pure-Rust core, no FFI; dead_code allowed crate-wide via `cfg_attr` in `src/lib.rs`), `c_abi` (extern "C" surface), `python` (PyO3 + `extension-module`, so even the wheel never link-imports `python3.dll`). The two consumer features are independent and composable — enable both for the maximum surface (what CI lints).
- **Test:** `cargo test --lib`
- **Lint:** `cargo clippy --all-targets --lib --features c_abi,python -- -D warnings` (the union-of-all-features gate; CI also runs `cargo check --lib` for the bare-default build, see `.github/workflows/ci.yml`; `main` is branch-protected on the strict clippy check). **Local gotcha:** the `python` feature pulls PyO3 `abi3-py312`, so this aborts with `cannot set a minimum Python version 3.12 higher than the interpreter version 3.11` when the ambient `python` on PATH is older than 3.12 — prefix it with the 3.12 venv interpreter. **`PYO3_PYTHON` must be an ABSOLUTE path**: the pyo3 build script runs the interpreter from its own working directory, so a repo-relative `.venv/Scripts/python.exe` fails with `failed to run the Python interpreter at .venv/Scripts/python.exe (os error 3)` in both PowerShell and bash. Use `PYO3_PYTHON=D:/Github/crimson-rs/.venv/Scripts/python.exe cargo clippy --all-targets --lib --features c_abi,python -- -D warnings`. CI is unaffected (it pins 3.12); the `c_abi`-only build has no PyO3 and needs no Python.
- **Workflow:** develop on `dev` → PR to `main` → CI green → merge. That's the whole loop — **there is no publish step.** `.github/workflows/ci.yml` (clippy + cargo test) is the only workflow and the required check on `main`. The old `build.yml`, which rebuilt a Windows wheel on every push to `main` and republished it as a rolling `v1.0.<minor>.x` "Development Build" pre-release, was removed 2026-08-09 — traffic showed no external consumers, so there is nothing to bump on a new patch series and no release to retire. Consumers build from source (`maturin develop --release` for the wheel, `cargo build --release --features c_abi` for the native dll/lib). **Fork gotcha:** this is a fork of `potter420/crimson-rs`, so `gh` defaults PRs to the *upstream* parent (they fail with "No commits between main and dev / Head ref must be a branch"). Run [`scripts/setup-fork-guards.ps1`](scripts/setup-fork-guards.ps1) **once per clone** (pins `gh repo set-default bbfox0703/crimson-rs`, `remote.pushDefault=origin`, disables `git push upstream`, and installs a `pre-push` hook that refuses any push to `potter420/crimson-rs` however it is addressed — the upstream is a ~1.03-era parent with nothing to send it), or always pass `gh pr create --repo bbfox0703/crimson-rs`. Never PR/push to upstream.

# Rules
- Ask before adding new dependencies to Cargo.toml.
- Binary format must roundtrip (read and write back identically).
- Custom types for binary serialization: `CString` (u32 len + len bytes — NO trailing NUL; this is what `iteminfo.pabgb` uses), `BString`-shape (u32 len + len bytes + u8 NUL terminator — used by `skill.pabgb` entry names + the PAPGT group_names_buffer; no shared Rust type yet, handled inline in `src/skill_info/mod.rs`), `optional<T>` (u8 flag + T if nonzero), `array<T>` (u32 count + count × T), `Variant` (u8 tag + match on tag).

# Binary Exploration
- For a first look at an unfamiliar binary, write partial `.hexpat` patterns in `references/` and iterate with `plcli run -i <file> -p <pattern.hexpat> -v -d`.
- For cross-version drift, use the tandem-walk / `diff_<old>_<new>.py` workflow and the Rust `_probe_*` tests in [`scripts/CLAUDE.md`](scripts/CLAUDE.md) — they diff two versions, which a pattern file can't.

# Module map
`src/` is organized as: `binary/` (PAMT/PAPGT/PAZ/PALOC/trie/paver container formats + the test-only `gamedata_layout` archive-path resolver), `crypto/` (Jenkins checksum + ChaCha20), `item_info/` + `skill_info/` + `string_info/` + `character_info/` (byte-roundtrip parsers), `save/` (save header + crypto + body), and `c_abi/` (the feature-gated extern "C" surface). The full annotated per-file map is in [`docs/c-abi-surface.md`](docs/c-abi-surface.md).
